# RTX 5090 (sm_120) — quality → memory → speed

Serve a dense 27B (NVFP4 weights) with an NVFP4 KV cache and 262k context
on a single 32 GB consumer card. If you have an sm120 5090, this is the
whole path: get the stack, pull the model, serve, warm up, verify.

## 1. What you need

- **RTX 5090** (32 GB, sm_120). The optimization order here is
  quality → **memory** → speed ([framing](../README.md#the-framing)) —
  memory is the scarce resource, which is what every decision below turns on.
- A current NVIDIA driver with Blackwell / sm120 support.
  <!-- TODO: verify exact RTX driver version in production -->
- **Cap the GPU at ~570 W.** The 5090's millisecond load transients can
  trip a PSU's over-current protection and present as *hard crashes that
  look like driver failures* — they aren't. The cap has kept the box
  stable at negligible throughput cost
  ([node profile](../nodes/rtx-5090.md#the-box)).

## 2. Get the stack

The serving path is a custom sm12x vLLM build carrying the
consumer-Blackwell NVFP4-KV enablement line (vllm#46329 kernels +
flashinfer#3684). Image line, commit stack, the sm120 FlashInfer pin
(**0.6.14**), and the local build patch are documented in
[`build-stack.md`](build-stack.md).

> Prebuilt container images are planned — they will replace the
> source-mount build below. Until then, build from `build-stack.md`.

## 3. Get the model

```
rdtand/Qwen3.8-27B-PrismaAQUA-5.5bit-vllm
```

Rob Tandler's ([@RobTand](https://github.com/RobTand)) PrismaQuant **AQUA**
mixed-precision export of Qwen3.8-27B: NVFP4 weights + FP8 attention,
~5.5 bpp, `compressed-tensors` format, Apache-2.0. **~24 GB on disk**
(5 safetensors shards, ~22 GiB). vLLM downloads it on the first
`vllm serve <hf-id>` — no separate fetch step; it is not gated.

This lab measured a self-produced AURA export against the maintainer's
reference at full-split parity (GSM8K n=1319, McNemar p=0.883) — the
strongest evidence a quant method can get, reproduced on independent
hardware ([note](../notes/qwen36-aura-head-to-head.md)). The AQUA export
above is the current production checkpoint.

## 4. Serve

```
vllm serve rdtand/Qwen3.8-27B-PrismaAQUA-5.5bit-vllm \
  --served-model-name qwen3.8-27b \
  --kv-cache-dtype nvfp4 \
  --enable-prefix-caching \
  --max-model-len 262144 \
  --max-num-seqs 2 \
  --block-size 32 \
  --gpu-memory-utilization 0.97 \
  --enable-chunked-prefill --max-num-batched-tokens 4096 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --reasoning-parser qwen3
```

Key decisions, each measured:

- **NVFP4 KV cache is the whole game on 32 GB.** It is what lets a 27B with
  long context fit at all: KV pool headroom **~469k tokens, ~4× what fp8 KV
  would allow** ([node profile](../nodes/rtx-5090.md#serving)).
- **Serve uncalibrated (vLLM's default k/v scale = 1.0).** Baked per-tensor
  amax KV scales — best practice at fp8 — *cost* 1.67 pp GSM8K at 4 bit,
  because block scales underflow fp8-e4m3 in attention-sink layers:
  uncalibrated **94.92% vs calibrated 93.25% (n=1319, McNemar p=0.013)**;
  rare sink outliers clip harmlessly at the block ceiling, needle-verified
  to ~240k tokens (README finding 2026-08-01). The AQUA checkpoint carries
  no baked KV scales, so this is the default — nothing to set.
- **Prefix caching on** (`--enable-prefix-caching`) — agents re-send huge
  contexts every turn; parity with the GB10 recipe.
- **Parser flags are load-bearing for agent traffic:**
  `--reasoning-parser qwen3` +
  `--enable-auto-tool-choice --tool-call-parser qwen3_coder`.
- **No speculative decoding.** The one clean drafter (DFlash2) forces fp8 KV
  — which halves context, the wrong trade on a memory-bound box — and the
  `--kv-cache-dtype-skip-layers` escape that would keep target KV at NVFP4
  is ruled out: skipped-layer pages pad to the hybrid model's state-page
  granularity, demanding ~41 GiB of KV for a 32k window
  ([batch-sweep + skip-layers note](../notes/dflash2-batch-sweep-and-skiplayers.md)).

## 5. First boot discipline

The 27B is a hybrid linear-attention model, and its GDN path has a
first-step failure window: **≥2 concurrent prefills in the very first
engine step after boot** can crash the engine
(`cudaErrorNotPermitted` in the GDN state write). A restart policy turns
that into a crash-loop hazard on any reboot into live traffic. Reproduced
on the GB10 so far, but the mechanism is the shared hybrid path
([note](../notes/gdn-first-step-crash.md)).

Every boot path therefore ends the same way: **wait for the health
endpoint, send exactly one small completion request, then open the door
to concurrent traffic.** Cost: one request.

## 6. Verify

Smoke test once healthy and warmed:

```
curl -s localhost:8000/v1/chat/completions -H 'content-type: application/json' -d '{
  "model": "qwen3.8-27b",
  "messages": [{"role":"user","content":"What is 84 * 3 / 2?"}],
  "temperature": 0
}'
```

Expect **126**, and **~72 tok/s single-stream** decode — the interactive
tier ([node profile](../nodes/rtx-5090.md#serving)).

Confirm the KV pool at startup in vLLM's log: the
`GPU KV cache size: … tokens` line should report on the order of **469k
tokens**, and `Maximum concurrency for 262,144 tokens per request` should
be ≈1.8×. If the pool is far smaller, KV is not actually NVFP4 (or an amax
scale slipped in).

## 7. Known limits

- **Long-context and multi-agent work belongs on the GB10.** This box is
  the latency tier; a length-based routing rule pushing long jobs to the
  128 GB box is on the list ([node profile](../nodes/rtx-5090.md#what-it-actually-does)).
- **Speculative decoding is not available here without giving up the memory
  win.** The remaining paths, in order of appeal: upstream NVFP4 non-causal
  kernel support (the skip-layers result sharpens the case for it), or
  context capping + length-based routing
  ([note](../notes/dflash2-batch-sweep-and-skiplayers.md)).
- The full-split quality verdict cited above is the *KV-format* decision
  (uncalibrated NVFP4-KV, sm120). Weight-format end-to-end verdicts for the
  AQUA export were measured on the GB10.
