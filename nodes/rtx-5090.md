# The sm120 node: RTX 5090 in a Kubernetes server

The lab's latency tier: a consumer RTX 5090 (32 GB) in a home-lab server
that runs a real Kubernetes stack — the point being that "local AI" here
means production plumbing, not a demo notebook.

## The box

- **RTX 5090**, 32 GB GDDR7 — roughly 7× the memory bandwidth of the
  GB10, one quarter of the memory. Hence the opposite optimization order
  ([framing](../README.md#the-framing)): quality → **memory** → speed.
- Runs as a node in a small Kubernetes cluster (Talos Linux, GitOps via
  Flux — every serving config is a commit, rollbacks are `git revert`; the objects are in
  [`deploy/neo26/`](../deploy/neo26/)).
- **Power lesson:** the 5090's millisecond load transients can trip a
  PSU's over-current protection — presenting as hard machine crashes that
  look exactly like driver failures. They weren't. A 550 W power cap on
  the GPU has kept it stable since, at negligible throughput cost
  (570 W was not enough for the transients).

## Serving (since 2026-10-11)

**Qwen3.8-27B as the 13 GB GridBook artifact, with its BF16 vision tower
reattached and abliterated in format** —
[TechPrototyper/Qwen3.8-27B-GridBook-13GB-vision-abliterated-vllm](https://huggingface.co/TechPrototyper/Qwen3.8-27B-GridBook-13GB-vision-abliterated-vllm),
built on [rdtand](https://huggingface.co/rdtand)'s
[GridBook-13GB export](https://huggingface.co/rdtand/Qwen3.8-27B-PrismaAQUA-gridbook-13GB-5080-vllm).
It runs on stock vLLM nightly + FlashInfer 0.7.1 + the GridBook plugin
([image and serve command](../containers/stock-nightly/)).

- **NVFP4 KV cache + 13 GB weights = a 765,668-token pool** at 262k context
  and eight parallel sequences. That is what lets one 32 GB card carry
  eight agents with mostly < 100k contexts.
- **~59 tok/s** single-stream decode, ~153 tok/s aggregate at four streams;
  prefill ~5.2k tok/s at 8k, ~2k tok/s at 240k.
- **Vision is mandatory** — screenshots, documents and photos arrive in agent
  sessions. The vision tower stays BF16 and off the FP4 GEMM path.
- **Prefix caching on** — agents re-send huge contexts every turn.
- **Speculation off.** Draft weights and draft activations come out of the KV
  budget. On this card, context and the prefix cache matter more than
  single-stream speed. The August line showed it can be done
  ([#53977](https://github.com/vllm-project/vllm/pull/53977)–[#53979](https://github.com/vllm-project/vllm/pull/53979),
  [DFlash2 × NVFP4](../notes/dflash2-nvfp4-sm120-spec-serves.md),
  [MTP on GridBook](../notes/rtx-gridbook-mtp-cutover-2026-08-31.md)). It will
  be re-evaluated on the new base.

## The gateway

A LiteLLM gateway in front of both inference boxes makes them one API.
Since September the split is **by model and job**, not by load:

- **Qwen3.8 on this card** — agents, code, tools, vision, eight parallel
  sessions.
- **Gemma-4 on the GB10** — German prose, minutes and letters
  ([`nodes/dgx-spark-gb10.md`](dgx-spark-gb10.md)).

The August session-count overflow from this card to the GB10 was retired
when the GB10 changed roles. It is commented out in Git, not deleted, so the
rollback is one revert.

The gateway's manifests and callbacks (reference state of 2026-08-31, when
the overflow was still live) are in
[`deploy/inference-gateway/`](../deploy/inference-gateway/).

## What it actually does

Interactive agent sessions — the harnesses people actually type into —
plus the cluster's ingress, API management and the multi-user agent gateway.
Bulk storage, and later services that don't need the GPU, go to the new
worker nodes as they join ([`homelab.md`](homelab.md)).
